# 阶段流程（A–G）

### 阶段 A：需求与约束
- 明确：站点目的、目标读者、内容类型与数量、更新频率、是否需要评论/统计
- 明确：风格关键词、参考站点、**验收硬标准**
- 明确：部署位置（域名/子路径）、预算上限
- 产出：`brief.md`（目标、栏目、风格、约束、非目标）
- **退出**：用户确认 brief；风格方向有 1 张首屏小样确认

### 阶段 B：信息架构与内容模型
- 站点地图：首页 / 列表 / 详情 / 关于 / 统计 / 友链 …
- 内容类型与字段（标题、日期、分类、章节、摘要、标签、封面；字段与默认值见 `references/content-model.md`）
- URL 规则与编号规则（如按分类独立编号）
- 导航层级：一级 + 二级（分类/筛选）；二级可收起、点空白收起
- **退出**：栏目与 URL 表确认；空状态文案确认

### 阶段 B2：技术栈选型与用户确认（动代码前必须完成）

> **GATE（本技能内最高执行门禁，但低于用户明确指令）**
> - 默认顺序：请求授权 → 探测本机 → 记录版本表 → 再给候选；**没有版本表不得给技术栈候选或推荐**。
> - 用户明确说"不用查本机 / 直接推荐 / 跳过"：按用户指令执行，推荐里必须标注"未探测本机，仅通用建议"。
> - 用户拒绝授权：按"跳过"处理，不擅自扫描。

1. **要权限并探测**：一句话说明用途（只读版本，不装不改），获同意后执行并记录：
   - `node -v`、`npm -v`、`pnpm -v`
   - `python --version`、`pip --version`
   - `git --version`
   - 浏览器是否可用（Chrome / Edge）
   - 输出表格：工具 / 版本 / 是否可用 / 备注
2. **检索最新方案**：搜当前稳定版本、维护状态、已知问题；覆盖框架、样式、内容方案、部署平台、图标/字体来源。
3. **给 2–3 个候选对比**：优先已装工具；需要新装的必须写安装代价；用户选了需新装方案时，先确认再装。
4. **落盘**：把环境版本表 + 最终组合一起写进 `brief.md`；用户说"随便"也要讲清推荐理由，不静默拍板。
- **退出**：用户确认组合；版本已记录；未确认前不进阶段 C

### 阶段 C：工程骨架
- 按确认的技术栈初始化；静态优先
- token 先定，再搭组件；内容用 schema 校验并给默认值；公式按需接 KaTeX
- **子路径部署必做**：`base` + 统一 `url()`（见 `references/scaffold.md`）
- 产出：导航/页脚/列表/详情/404 空壳
- **退出**：构建通过；本地可点通全部路由

### 阶段 D：设计系统
- 颜色 token + 亮暗两套；字体 1 标题 + 1 正文（免费可商用），woff2 子集 ≤150KB
- 间距/圆角/阴影变量统一；按钮、卡片、标签、输入框四类基础组件
- **退出**：亮/暗截图对照；390/768/1280 三档正常

### 阶段 E：页面实现（按页推进）
顺序：首页 → 列表 → 详情 → 关于 → 统计/归档/标签 → 404
每页完成：内容真实、亮暗正常、390px 不横向滚动、无开发日志文字
- **退出**：全部页面本地可达，console 无报错

### 阶段 F：优化
按 `skills/performance/SKILL.md` 的预算表测量并记录 before/after；未达标不部署
- **退出**：预算达标；Lighthouse 移动端 ≥85

### 阶段 G：验证与部署
按 `skills/qa-launch/SKILL.md` 执行；本地预览 → 用户说"推" → 部署 → 线上验证
- **退出**：关键页 200 且元素存在；用户确认
