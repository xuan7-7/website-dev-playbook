# 互动式需求具象化

用 A/B/C +「其他」逐轮确认，直到需求可直接落成页面。每轮 3–4 题，不一次抛十几个问题。

**用户原话是硬约束**：风格形容词/名词逐字保留，不替换近义词、不概括成通用分类；只有用户没给词时才提问补充。

## 第 1 轮：目标与范围
- 站点类型：A 个人博客 / B 作品集 / C 产品落地页 / 其他
- 受众：A 自己 / B 朋友与同好 / C 公开访客 / 其他
- 内容量：A 3–5 页 / B 6–15 页 / C 15+ 页 / 其他
- 是否要评论/统计/搜索：多选或"都不要"

## 第 2 轮：风格与参考
- 风格：**逐字保留用户原话**（如用户说"粉白、手账感、二次元"，就原样列为 A/B/C 选项），不翻译、不概括、不替换成通用风格名；用户没给词时再问要关键词
- 色彩倾向：A 浅色为主 / B 深色为主 / C 两套 / 其他

## 第 3 轮：部署与约束
- 部署：A GitHub Pages / B 其他静态托管 / C 先本地
- 其他约束：预算、时间、不能用的技术/框架（自由补充）

> 技术栈、环境探测、是否允许项目内新装依赖，统一在阶段 B2 确认，本问卷不重复问。

## 第 4 轮：验收
- 必须有的页面/功能（逐条列）
- 明确不要做的（非目标）
- 验收硬标准：移动端 / 暗色 / 性能 / 内容

## 记录规则
- 每轮答案写进 `brief.md`，未确认项标「待定」，不替用户默认
- 用户跳过的问题不追问第二次
- 用户说"随便"：给推荐项与理由，仍要用户确认
